Troubleshooting

If LocalCompanion does not start or behaves unexpectedly, check this page first.

Will not start

Double-clicking the exe does nothing / the app closes immediately

.NET 10 Desktop Runtime (x64) may not be installed.

  1. Open https://dotnet.microsoft.com/download/dotnet/10.0.
  2. Download and run the x64 .NET Desktop Runtime installer.
  3. Launch LocalCompanion.exe again.

If the app is already running, a message appears and the second copy exits. Check the existing window, the taskbar, or another desktop.

A message says the app is already running

Only one LocalCompanion window can run at a time. Use the window that is already open.

The app starts but the chat area is blank / empty

Microsoft Edge WebView2 Runtime may be missing (required).

The conversation view uses WebView2. It is not bundled in the ZIP. Windows 11 usually includes it. It is separate from the Edge browser app.

  1. Open https://developer.microsoft.com/microsoft-edge/webview2/.
  2. Download and run the Evergreen Bootstrapper or Evergreen Standalone Installer.
  3. Launch LocalCompanion.exe again.

Errors such as “Unable to start the application”

  • Windows 10 version 1809 (build 17763) or later is required. Apply Windows Update if your OS is older.
  • If you removed language folders such as en, en-us, or ja from the extracted folder, the app may fail to start. Extract the ZIP again.

SmartScreen: “Windows protected your PC”

This app is not code-signed yet, so SmartScreen may appear on first launch. Choose More info → Run anyway. Confirm that you obtained the ZIP from a trusted source.

First-time setup fails

About the first-time setup screen

  • On first launch, after language selection, a first-time setup screen appears.
  • Continue with default setup prepares llama.cpp and downloads the default model Gemma 4 E2B (QAT).
  • Choose folder lets you point at your own GGUF folder and skip the default model download (read-only; your files are not modified).

llama.cpp / model download fails

  • First launch requires an internet connection.
  • Restarting the app many times in a short period may hit a download source limit (403). Wait about an hour and try again.
  • If downloads are blocked on a corporate network, set up on another connection and move the folder afterward.

“DLL not found” errors

Visual C++ Redistributable (x64) is required.

  1. Open the Microsoft VC++ redistributable page.
  2. Download and install the X64 package.

Chat does not work

Status never shows OK

  • Check the runtime status on Settings → Model (the same status also appears at the bottom-right of the chat screen).
  • Starting llama-server can take several minutes (especially on first launch or with large models).
  • If another AI app or server app is running, close it. If the problem continues, restart the PC.
  • A leftover llama-server that you started by hand can occupy the port. End it in Task Manager and try again.

Replies are extremely slow

  • The app may be running on CPU only. Check the execution backend (CUDA / Vulkan / CPU, etc.) on the Model tab in Settings.
  • If memory is tight, try a smaller model (higher quantization GGUF). You can choose another GGUF or an additional models folder on the Model tab.

Models missing or will not switch

  • An additional models folder on the Model tab is read-only. You do not need to move files into the app folder.
  • After changing models, press Apply model (restart llama).
  • If mmproj is required for vision, it is downloaded to the app models\ folder when missing from your folder.

Settings tabs

  • General, Model, Character, RAG, and About are always shown. Long-term memory toggles live under General.
  • The VOICEVOX tab appears only when VOICEVOX is installed on this PC.
  • Version, licenses, logs, and backup are under Settings → About.

Long-term memory

  • Turn on Use long-term memory under Settings → General. Memories are stored per named character; the default AI has no long-term memory.
  • Short facts are stored on this PC and may be recalled naturally in that character's chats. There is no on-screen list or manual add (internal storage only).
  • With Auto-extract memories when a chat ends enabled, the local AI may save up to 3 short facts for that character when you end a named character's chat or close the app. Recent turns in the same conversation are handled by the chat History option.
  • If memory never appears, check that memory is enabled and that a named character conversation has enough back-and-forth.

When you switch characters

  • Switching characters starts a new conversation. Messages from another character are not mixed into the previous session.
  • To continue an earlier chat, select that session from the left history pane.

Speech input does not work

  • Enable Use speech input under Settings → General.
  • Allow microphone access under Windows Settings → Privacy & security → Microphone for desktop apps. If access is off, chat shows guidance.
  • Click the microphone button next to the chat input to start recognition. Click again to stop (it may also stop automatically after one utterance).
  • Recognition fails if no microphone is available or another app is using the mic.
  • Even with the English UI, Japanese recognition may be used if the English speech pack is not installed. To speak in English, add English speech recognition in Windows Settings.
  • If VOICEVOX playback seems quiet after speech input, restart LocalCompanion or try again.

Text-to-speech (VOICEVOX) does not work

  • Install VOICEVOX separately. The installer UI is in Japanese; chat works without VOICEVOX.
  • The VOICEVOX tab is hidden until VOICEVOX is installed. Restart LocalCompanion or reopen Settings after installation.
  • On Settings → VOICEVOX, enable speech and choose a speaker. Changes are saved automatically.
  • Port 50021 must be free for the VOICEVOX engine.
  • If VOICEVOX is installed in a non-default location, start VOICEVOX first, then start LocalCompanion.

Chat behavior

  • Conversations with the default AI (no character selected) are not listed in the left history pane.
  • Under chat Options, turning off Reasoning may stabilize replies.
  • With History off, prior turns are not sent to the model.
  • URL attachments are limited to 2 MB (separate from RAG import limits).

Vision / image input fails

  • The main GGUF and mmproj files must match.
  • On the Model tab in Settings, confirm that mmproj is configured.
  • If Insert image in chat is disabled, mmproj may be missing or the model may not support vision (runtime status “OK” alone does not prove vision works).

RAG (document search) does not work

  • Ingestion and search use the llama-server embedding API. Wait until status is OK.
  • By default, imports are limited to about 32 MB per file and 500 files per folder. Change RagMaxFileBytes (bytes) and RagMaxFolderFiles (count) in appsettings.json (0 or less means unlimited).
  • Scanned image-only PDFs (with no text layer) are not searchable yet; OCR is not implemented. Use text PDFs, Markdown, or plain text. This is separate from reading text in a chat image attachment (Vision).

Privacy and network

  • Conversation, RAG, and attachment text are processed on this PC.
  • Optional update checks may contact GitHub; when VOICEVOX is installed, VOICEVOX update checks may also contact GitHub.
  • First-time setup and mmproj download may access Hugging Face and similar hosts.
  • Loading a URL, URLs written in a message, or research-style web search may access those remote sites. The default web search uses DuckDuckGo (HTML) and sends the query to that service. Set WebSearchEnabled to false in appsettings.json to turn it off.
  • Speech input uses Windows speech recognition, which may be online depending on your environment.

To see the actual folder, use Settings → About → Open log folder.

Backup and restore

  • Use Settings → About → Back up data to export conversations, RAG, and settings to a ZIP file.
  • To restore, exit the app and extract the backup ZIP into the data folder listed above.

Still stuck?

  1. Exit the app.
  2. Delete the tools\llama-cpp\ folder inside the LocalCompanion folder (it will be downloaded again on next launch).
  3. If that does not help, back up your data from Settings, move the data\ folder somewhere else, and try a clean start.
